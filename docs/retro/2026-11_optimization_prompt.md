## Порядок работы: 3 захода

Каждый заход идёт в отдельной сессии. Начинай с чтения `docs/retro/optimization_status.md`, заканчивай его обновлением: что сделано, что решено, что дальше, что проверить. В первом заходе создай этот файл.

### Шаг 0. Гигиена (начало захода 1)

Рабочая папка: `C:\Roblox\NightOfTheDead`. По каждому действию покажи мне точную команду и результат. Сначала сверь состояние: `git status --short`, `git branch --show-current`, `git worktree list`, `git ls-files --eol`.

1. **Вернуться на `main`.** `git switch main`, затем `git pull --ff-only origin main`.
2. **Нормализовать переводы строк.** Поставь первой строкой `.gitattributes` правило `* text=auto eol=lf`, правила LFS оставь. Рабочее дерево должно быть чистым: сначала разберись с незакоммиченным. Затем:
   - `git add .gitattributes` и отдельный коммит;
   - `git checkout-index --force --all`, чтобы переписать файлы на диске;
   - проверка: `git ls-files --eol` не показывает `w/crlf`.

   `git add --renormalize .` не нужен: в индексе и так LF.
3. **Убрать старые worktree и ветки.** Для каждого из `.claude/worktrees`: `git -C <путь> status --short`. Пусто — `git worktree remove <путь>`. Не пусто — покажи мне и не трогай. Затем `git worktree prune` и `git branch -d <ветка>` для влитых веток. `-D` не использовать.
4. **Экспорт места.** Это делаю я: Studio → File → Save to File As → `.rbxl`. Подскажи шаги и проверь, что файл есть. `Remu4in/TNOD` публичный, поэтому файл места клади в приватный репозиторий или в отдельную папку бэкапа, но не туда. Спроси меня, куда.
5. **Пуш.** Только после моего подтверждения: `git push origin main`.
6. Обнови раздел про синхронизацию в `CLAUDE.md`, если решим перейти на Rojo. Сейчас он описывает работу без Rojo, и Rojo не установлен.

## Ограничения

- Игру `NightOfTheDead` и файл её места не менять, кроме шага 0. Читать можно.
- Выпуск игры этим промптом не закрывается. Релизные пробелы (ретроспектива, 3.10) — отдельная задача.
- Ничего не публиковать и не пушить без моего слова.
- Для сторонних плагинов, MCP-серверов и скиллов — проверка через `skill-vetting` до установки. Установку спрашивай у меня.
- Скиллы должны быть короткими: подробности в отдельных файлах, которые читаются по необходимости. Не раздувай описания.
- Скиллы делай переиспользуемыми: движок-независимое ядро плюс адаптеры под Roblox и Godot. Для примеров бери первый проект, но не зашивай его детали в скиллы.

## Критерий готовности

- Есть один документ воркфлоу, и каждый скилл ему соответствует.
- Шаг 0 выполнен, результат каждой команды записан в файл статуса.
- `world-forge`, `asset-vetting` и, если решим, `game-development` лежат в `C:\gamedev-studio`, дубли убраны.
- Каждая проблема из разделов 3.1–3.9 ретроспективы либо закрыта конкретным изменением, либо явно отложена с причиной.
- Шаблон проекта запускается, пилоты пройдены, результаты записаны.
- В конце — отчёт: что изменено, что проверено, что осталось.

Начни с чтения файла статуса (если его нет, создай), затем шаг 0.
